## バグ修正(コミット ded54c6)

**現象**: `all goroutines are asleep - deadlock!`(size 10 / 16 コアで再現)

**根因**: `split()` が実セル(1..len-2)ではなく配列全体(境界セル込み)を対象にループしていた。
結果として、

1. 右境界セル(www)を start とする切片が生成される → slice 長 2 → interior 空
2. interior 空 → `firing()` がいつも真 → goroutine は t=0 で「発火済み」として即退出
3. 隣接 goroutine は退出を知らず、バッファ 1 のチャネルに送り続けて詰まる → 全停止
4. また `NumCPU >= size+2` のとき n=1 となり最初の切片 `[0:2]` も空になる

**症例**: 7 コアに偽装すると size 11/14/17/23/29 のみデッドロック(切尾の位置ずれが slice 長 2 を作るアライメント)。
それ以外は常に正確に 2n−2 で発火 → 中身のダブルバッファ+チャネル同期の設計自身は正しい。

**修正**: 実セルだけを対象に分割し、各 goroutine が最低 1 実セルを interior に持つ(slice 長 >= 3)よう保証。
検証: size 2〜128 全部で全セグメント同一の t=2n−2 で発火。

### 実装メモ(並列設計の要点)

- 実セルの所有権は排他的。各セグメントは「左隣 1 セル + 実セル群 + 右隣 1 セル」の slice を持つ。
- 二重バッファ(cur/nex)は全セグメントで共有し、各ステップ終了後 1 つずつ隣トークン交換(送信2+受信2/ステップ)。
- トークンはメモリバリアでもある: 自分の次ステップの境界読み取りは、隣の same-step 書き込みの後に行われる。
- 外部セル(www)は初期化後に誰も書かない → どのレベルで読んでも常に有効。

### v5(k=2 バッチ)が成立しなかった理由(設計上の欠陥)

単一セグメントでは全 size 正しく同期するが、複数セグメントで全滅。本体:

- バッチ内 j=0 が担当外のハロセル [Lo-1, Hi+1] を書き込むため、**同じ物理バッファに異なるレベルの値が別セグメントから同時書き込まれ衝突**する(例: 自分の j0 が cell lo-1 を level B+1 で、左隣の j1 が同じ buffer の同じセルを level B+2 で書き、後勝ちが非決定的)。
- 逐次ステップ版(v1/v2)は所有権排他でレベル書き込みが 1 対 1 なので問題ない。**「halo を書く = 書き込み所有権の排他性が崩れる」**ことが本質。
- 修正には私的配列 + 境界値のメッセージ交換が必要で、メッセージ数はむしろ増える(halo 幅ぶん)。得るものがない → 却下確定。

### SIMD 検討(2026-10-13、rust スクラッチプロトタイプ実測)

内側ループは `idx = (l<<8)+(c<<4)+r` のランダムなテーブル参照が本体で、ベクタ化には **AVX2 gather(vpgatherdd、scale=1 のバイトオフセット参照)** を使う。表は u8 配置のまま(8KB、L1 常駐)、gathered dword の下位バイト = 状態を回収。u8 化(セル・表とも)は AVX2 の前提でもある。

スクラッチ(`/tmp/fssp-simd`、sequential・同期なし、合成ルールでバリアント間の進化バイト等価チェック済み):

| 変種 | per-op | 備考 |
|---|---|---|
| usize スカラー(現行と同形) | 1.03ns | 1 op ≒ 4.3 cycle |
| u8 スカラー | 1.03ns | **効果なし**(メモリは既に全キャッシュ内、律速は計算側) |
| **AVX2 gather (u8)** | **0.235ns** | **4.4x**(≒ 1 cycle/cell、n=20k〜200k で一定) |

- **リポジトリ rust への組み込み完了(2026-10-13)**: 全セル `usize → u8`(パーサ・fired・new_line/first_line も)、ルール `[u8; 8192]`、`simd::step`(32 セル chunk + scalar tail)を `nextline_par` に導入。`is_x86_feature_detected!("avx2")` を main で 1 回判定してフォールバック(スカラー)を保持。size 2..64+256 全通過、size 10 の最終状態は ruby と一致。

### SIMD 導入後の並列実測(rust、16論理):

| size | 変更前(スカラ) | AVX2 | 倍率 |
|---|---|---|---|
| 10,000 | 0.13s | 0.11s | 1.2x |
| 25,000 | 0.52s | 0.36s | 1.4x |
| 50,000 | 1.30s | 0.75s | 1.7x |
| 100,000 | 3.79s | **1.82s** | **2.1x** |
| 200,000 | 12.6s | **5.35s** | **2.3x** |

golang(4.29s @100k、16.6s @200k)に対して rust AVX2 は **2.3〜3.1x**。この規模では計算 ≈ 0.4s、同期 ≈ 0.9s+ と同期が再び主要因になりつつある(次の最適化対象)。
- 32 セル/chunk の構成: 3 loadu + unpacklo/hi×3 + idx 計算(slli/add) + 4 cvtepu16 + 4 gathers + 対応づけ(shuffle+and)4 + half 内詰め(extract+bslli+or)→ 32B storeu。末尾は scalar。
- AVX-512(zmm gather、16レーン/inst)はこの CPU(Tiger Lake)で可用だが 512bit 演習時のダウンクロックがあり、AVX2 版を先に採るのが無難。Rust は stable intrinsics(`std::arch::x86_64`)で足りる(nightly 不要)。
- スクラッチの main.rs はバッチの検証用として残すこと(リポジトリ外)。

### rust の -d(ダンプモード、2026-10-13 追加)+ -c(色付き)

`fssp.exe [size] -d`: 1 ステップごとに途中経過を出力。**ruby の `-d` とバイト完全一致**する書式(名前を | 連結・色なし、size 2/3/4/5/10/15/17/23/40 で diff 検証済み)で、ruby ↔ rust の直接突き合わせ検証に使える。ダンプモードは逐次実行(並列はステップ同期の中に全体を一つのタイミングで参照できる地点がないため)。並列パスの変更はなし。

`-c` / `--color`: dumpln と同じ 24bit ANSI 色(ルールファイルの前/背景色)でダンプする。-c 単独は -d を兼ねる。プレーンな `-d` は diff 検証用にそのまま維持。

### rust のルールファイル指定 (-r / -s / -h、2026-10-13)

`fssp.exe -r ../mazoyer.rul.txt [-s size] [-d] [-c]`。**ルールファイルは必須**(既定値は持たない)。セル数も `-s` / `--size` のオプションにした(既定 10)。位置引数は取らない。`-r` / `-s` は値を取るので引数ループを `for` から index の `while` に変更。golang/ruby は未対応。

- `-r` なし / 値なし → `rule file is not specified` / `-r: value is required` + usage を出して exit 1
- 解釈できない引数 → `unknown argument: ...` + usage を出して exit 1。`-s` に非数値 → `-s: invalid size: ...`
- `-h` / `--help` → usage とオプション一覧を **stdout に** 出して exit 0(エラーではないので stderr には出さない)。他の引数と併用しても help が優先。usage の複数行文字列は `\` による行継続だと次行の先頭空白が食われるので `concat!` で組んだ
- 開けないファイルはパスを含めたエラーを出す(従来はパスを含まないメッセージだった)

**なぜ必須にしたか**: 従来は数値に解釈できない位置引数を黙って捨てており、既定の waksman で走っていた。このため `fssp.exe balzer.rul.txt 5 -d` と打つと**何の警告もなく waksman が走り**、balzer が発火したように見える紛らわしい事故になった(実際に起きた)。既定を持たせないことでこの事故の余地自体をなくした。

リポジトリ直下に `mazoyer.rul.txt`(7状態/120規則)と `balzer.rul.txt`(9状態/182規則)を追加(出所: consoleCAS-SL1 の `app/*.rul`、MIT、改行は既存と同じ CRLF)。`mazoyer` は**無改造で size 2..40 すべて 2n-2 で発火**し、`rust -d` の出力が ruby `-d` と一致する(size 2..64 で確認)。SL1rule 形式のパーサは元から汎用だったことがこれで確認できた。

`balzer` は上流のファイルのままでは size 5,9,17,33,34 で未登録規則を引いていた。**発火状態 F を左辺に持つ規則が 1 つも無く**、途中で F が隣に現れるため(例 size 5: t=7 が `M M M F F`)。未登録の扱いが実装ごとに違う: golang/rust は状態0(= balzer では A)にフォールバックして**黙って誤動作**、ruby は nil でクラッシュ。general 位置を右端にすると第 1 ステップの三つ組 `(www, L, L)` が未登録で全サイズ即落ちする(このファイルは左端前提)。

**修正(2026-10-13、ルール表 1 行)**: `R ##B ##M` の遷移先が `Q` だったのを `A` に直すと全サイズで解決した。`C ##B ##M ->A` と揃う形なので上流側の転記ミスと思われる。修正後は ruby 参照実装で size 2..40、rust で size 2..60 に加えて 100/101/128/256/1000/10000 がすべて 2n-2 で発火し、**発火状態が最終ステップより前に一度も現れない(厳密な同時発火)**ことを確認。`rust -d` と `ruby -d` の出力も一致する。したがって未登録規則の扱い(吸収状態にする / エラーにする)を変える必要はなくなった。

### rust の故障区間指定 (-f / --fault、2026-10-13 追加)

耐故障 FSSP(Umeo 2004, e87-d_3_733.pdf)実装の第 1 ステップ。**故障区間を CLI で定義できるようにしただけで、シミュレーション挙動はまだ変わらない**(故障セルも通常ルールで動く。次ステップで 1/1 パイプライン中継を実装する)。

`fssp.exe -r ../mazoyer.rul.txt -s 11 -f 3-5,10 [--strict]`:

- `-f <list>`: 故障区間リスト。1 始まり、カンマ区切り。`a-b` = a..b(両端含む)、`a` = 単一セル。指定時は解析結果を出力する:
  ```
  cells: 11, defective: 3-5,10
  segments: I1[1-2] D1[3-5] I2[6-9] D2[10] I3[11]
  constraint n_i>=m_i (A1/A2): FAIL (D1 (I1=2 < D1=3))
  constraint n_i+m_i>=p-i (A3): OK
  note: defective cells are defined but not yet simulated (normal rules apply)
  ```
- ハードエラー(exit 1 + usage): 範囲外(1..n 外)、`a > b`、非数値、値欠落、区間の重複、**セル 1 / セル n の故障**(論文 §2.3.1「両端は正常区間」はモデルの前提)。
- **隣接する区間は統合**する: `-f 3,4` ≡ `-f 3-4`(統合しないと間に空の正常区間が挟まり I_i/ D_i の交互構造分析が壊れる)。
- `--strict`: `n_i >= m_i`(A1/A2 の前提条件、Theorem 2/3)を満たさない配置を実行せず exit 1。無指定時は stdout に FAIL を表示 + stderr に警告して続行(SPEC の「条件を満たさないケースを区別して記録」用)。
- A3 の追加条件 `n_i + m_i >= p - i`(Theorem 4、i=1..p、D_i と**左隣**の正常区間 I_i のペア)は常に表示のみ(拒否はしない)。
- データ構造: `FaultSpec`(正規化済み区間リスト)/ `FaultAnalysis { mask(n+2、セル配列と同インデックスの故障フラグ), segments(I/D 交互) }`。mask は次ステップで `first_line`/シミュレーターへ引き渡す前提。
- 回帰: `-f` あり/なしで `-d` のダンプ本体がバイト一致(size 10、mazoyer)、発火時間も同一。

**論文側の補足(実装で重要)**: 論文は「実装は与えない」と明記しており freeze/thaw 込みの遷移表は載っていない。故障区間の挙動の正式定義は Kutrib & Vollmar [9][10] 参照。本文は pdftotext で `.tmp_figs/e87.txt` に抽出済み(図・数式の記号は一部欠落、不等号は文脈から復元: `n_i >= m_i`、`n_i + m_i >= p - i`)。

### rust の故障セル中継 + 制御層実装(2026-10-13 追加)
第 2 ステップ。故障セルの双方向 1/1 中継と凍結/解凍の制御層をシミュレーターに実装。**遷移ルールファイルは未変更**(最終的な同期アルゴリズムのルールは後段で作る。今は freeze/thaw をセル状態とは別のチャネルで持つという確定要件に従った)。確定モデルは `Fault-Tolerant FSSP SPEC.md` の「故障セル中継モデルの確定定義」に記録。

**中継層**(`FaultField`):
- 故障セルは t=n で t=n−1 の左セルと右セルの状態を保持 = 2 本の方向ストリーム(`to_right`: L→R、`to_left`: R→L)の純シフト。`fault_step` は故障セルをルール表ではなくシフトで更新する。
- 正常セルのルール入力: 隣が故障セルなら、こちらへ向かって流れてきたストリーム値を(左隣からは to_right、右隣からは to_left)見る。境界での追加遅延なし、m セル区間の通過はちょうど m ステップ。
- 初期ストリーム = soldier 状態。故障セルの基本状態は不変(発火判定 `fired_intact` は正常セルのみで行う)。

**制御層**:
- `Ctrl::Freeze/Thaw/None` のチャネル。1/1 左向きに伝播し、到着したセルの状態変化を即時停止/再開。凍結データは `frozen: Vec<bool>`。故障区間は凍結せず通過する。壁で消滅。
- 凍結/解凍はセルごとに一様な歩数になる(Δt 一様性 — Lemma 1 の 2n−2+Δt の根拠)。

### CA 局所化 第 2 段: 複合状態機械の設計(2026-10-14、実装前設計)

FT と NG の CA 局所化を、論文の信号機構(§3 A2/A3)に忠実に設計した。

**時間解析により確定した正確な時刻構造**:

- **NG(次区間の将軍起動)**: I_i と I_{i+1} の間で、会合セル C≈I_i∪ D_i の中央で
  1/3 信号と反射信号が会合し、そこから 1/1 右向きの起動信号が出る。時間検証で
  `T_C + (R_i − C) = 2n_i+m_i−1`(cell R_i での表示時刻)→ 故障区間 +1 + (m_i−1) →
  `2(n_i+m_i)−1` に I_{i+1} 左端の左入力へ提示、`t_{i+1} = 2Σ`(厳密一致、**任意
  m_i で成立**)を確認。
- **FT(解凍)**: Δt_i = 2(n−R_i) = I_i の右端より右のセル数の 2 倍(簡単形)。
  論文機構は配列右端の壁反射から 1/1 左走行。検算では T3'(I_{p+1} 自身の壁 M
  事件を発生源とする装置)は一般の配置で時刻がずれるため、論文どおり「I_i 右端
  で生じる反射信号群の往復」で起こる。
- **A3 の +p は「区間左端での 1 ステップ停止」の機構**: a-signal は各故障区間の
  左端(= D_i 右端)で 1 歩停止し、これが +1/区間の累積。本実装の故障区間も
  「出口で 1 歩停止」の機械規則を入れれば A3 の時間が自動で出る(実装候補)。

### CA 局所化 第 2 段(実装第 1 弾): T3 と chateau+signal 複合 carrier(2026-10-15)

### CA 局所化 第 2 段(実装第 2 弾): A3 の a/b 会合解凍(②-C、2026-11-06)

A3(`--a3`、同期 2n−2+p)の**解凍 FT 注入を撤廃**し、論文 Fig.8 の a/b 往復対
(各 I_i の右端から配列右端へ往復し、自区間の右端で会合して解凍を起動)を
規則層+故障セル処理(rust 側)で実現した。ルールファイルに会合状態 `abX` があると
`plan_a1_signals` は A3 の FT 注入を自動で止める(`a1:` 注記に
「a/b meeting abX (rule layer, no injection)」と出る)。

- **前進対**: I_i 右端の担体 CB の入庫で D_i 左端が a 波 `aF`(先発)と b 波
  `bF`(1 歩後ろ)を to_right に書く(rust、one-shot)。未起床セル上を 1/1 で
  右走し、壁で `aF→T3`、`bF→bR` に反射(2 歩: 到達表示と反射表示)。
  - b の前進停留(論文: I_{i+1}..I_p の左端で 1 歩停留)= D_i 左端が**表示**
    の bF(=他区間から横断してきた b)を拾ったときだけ 1 歩遅延線に入れる。
    誕生区間 D_i では拾わず生成するので停留しない(局所判定、p−i 回)。
  - a の帰還停留(論文: 帰還時に各故障区間の左端で 1 歩停留)= D_i 左端が
    T3 族を拾ったときの 1 歩遅延線(D_p..D_{i+1} で p−i 回)。
  - a 先発・b 後発だと b は前進で遅れ、a は帰還で遅れるので対の間隔は常に
    ≥ 1(重ね合わせ状態が不要)で、**自対の D_i 左端でだけ「a 到着時に b が
    1 セル後ろ」**になる(他の D_j E_j では間隔 1+j−i ≥ 2)。会合判定は rust

  要る)、起床複合 `LT3` は純 T3 と別状態なので鏡も別状態 `LbR`、自身が波を運ぶ

### 故障セル処理の規則層化の可否判断(2026-11-07)

**問い**: rust 側にある故障区間 D_i の処理(遅延線・左端の会合判定・成分射影・右端の
1 歩記憶など)を、故障セルを論文どおりの純粋な 1/1 線にしたまま、両隣の正常セル
(I_i 右端、I_{i+1} 左端)の状態と規則に移せるか。移せないものは何か。

**判定基準**: CA であるとは、各セルの次状態が「自状態・左入力・右入力(+静的な
故障フラグ)」だけの関数であること。故障セルの模型は 2 通りある(論文 §2.3.2):
- (a) **純粋シフト線**: 「信号の情報も方向も変更せずに 1/1 で通す」。故障セルは
  左隣の状態をそのまま右へ、右隣の状態をそのまま左へ写すだけ(to_right[c](t+1) =
  左の状態(t)、to_left[c](t+1) = 右の状態(t))。
- (b) **固定の局所規則を持つ 2 レジスタ機械**: 同じ §2.3.2 の Kutrib–Vollmar の
  定義「故障セルは特定の様式で内部状態を変える」。シフトに加えて、自レジスタと
  両隣の入力だけから決まる固定規則を許す。論文自身も「第 2 反射は D1 の右端
  (故障セル)で生成される」と書いており、(a) ではこれは起こせない。

**結論の要約**: 現在の rust の故障区間処理は、**(b) の意味ではすでにほぼ局所**で、
非局所な入力は 3 つだけ(下記)。**(a) の意味では、1 点を除いて全て正常セルの規則に
移せる**。移せない 1 点は「会合セルが故障区間に落ちる対(m_i ∈ {n_i−1, n_i})の
NG 放出」で、これは機構の工夫では越えられない**情報論的な下界**に当たる。

#### 2. 情報論的な下界(純粋シフト線では m_i ≤ n_i − 2)

t_i = 0、I_i をセル 1..n_i、D_i を n_i+1..S(S = n_i+m_i)、I_{i+1} の左端を S+1 とする。
I_{i+1} の起動は「S+1 に将軍が t = 2S に表示される」こと(論文 Thm.2/3 の
t_{i+1} = t_i + 2(n_i+m_i))。m_i の情報が正常セルに届く経路は、1/1 信号が S+1 に
着く(t = S)→ その反射が線を戻る、の往復しかない(I_{i+1} は未起床で時計を持たず、
I_i は m_i を知らない)。純粋シフト線では反射は S+1 の表示(t = S)を線が写すので、
n_i+1 の線レジスタに現れるのは t = S+m_i、セル n_i がそれを右入力に見るのも
t = S+m_i。そこから右へ出せる最速の信号は n_i の表示 t = S+m_i+1 → 線 n_i+1 で
S+m_i+2 → 線 S で S+2m_i+1 → S+1 が入力に見て表示 t = S+2m_i+2。これが 2S 以下で
ある条件は **2m_i+2 ≤ n_i+m_i ⇔ m_i ≤ n_i−2**。A3 は起動が 2S+1 なので m_i ≤ n_i−1。
どんな信号速度・会合方式でも同じ(論文の 1/3 と 1/1 の会合が c = S/2+1 に落ちるのは
この下界に張り付いた結果。速度 1/k で会合させると到着時刻の制約から k=3 しか解が
ない)。論文は「会合セルは C_⌈S/2⌉ で n_i ≥ m_i なら I_i に属する」と書くが、本実装の
正確な時刻系では会合セルは S/2+1(偶数)/(S+3)/2(奇数)で、m_i ≥ n_i−1 のとき故障
セルに落ちる。論文の「D1 の右端で反射」(故障セルが反射する=(b) の模型)を許しても
下界は m_i ≤ n_i−1 までしか緩まず、m_i = n_i は 2n−2 では不可能。
**論文 Thm.2/3 の条件 n_i ≥ m_i は、純粋シフト線の模型では正確には達成できない**
(本実装は (b) の局所規則=D_i 左端セルが右隣のレジスタを見て放出することで達成)。

#### 3. (b) の模型での現状: 非局所な入力は 3 つ

1. `next_pair_deliverable`(最終区間かどうか=大域構造)。実験 `FSSP_NPD_ALWAYS=1`
   で常に真にすると、sweep_a1 36/305、sweep_a2 51/487、sweep_a3 169/1695 が落ちる。
   落ち方は時刻のずれではなく、最終区間に生まれた 1/3 信号 の重なりが宿主の鍵に
   透過していない生成器の網羅漏れ(例 n=6 -f 2: t=9 の I2 将軍が `(L, M, mS3A)`
   で発火せず M のまま。A1 の失敗は全て n_2 = 4、A3 の 169 件中 151 件が最終区間
   4 セル)。生成器に「1/3 信号 ⊕ 宿主」の透過鍵(発火を含む)と右壁での消滅鍵を
   足せば外せる見込み。
2. `distal_pick` の `p == 1` 分岐(p は大域)。A1/A3 を別の規則集合として固定すれば
   局所(上表)。
3. `own_wave`(線の入口レジスタを出口が参照する=同一線内だが別セル)。判定には
   もう使っておらず(`fold_at_distal` は own_pres)、削除できる。
   `this_pair_deliverable`/`cb_ok` は構造的に常に真で、削除できる。

これらを外せば、rust の故障区間処理は「2 レジスタ+少数のフラグを持つ故障セルの
固定局所規則」として、入力(左隣の状態または to_right、右隣の状態または to_left、
自レジスタ、静的フラグ)だけで記述できる。

#### 4. 推奨

- **(b) を正式な模型として採用する**: 論文 §2.3.2 の Kutrib–Vollmar の定義に収まり、
  論文自身の「故障セルでの反射」とも整合する。やることは 3 の 3 点(生成器の
  1/3 信号 透過鍵、A1/A3 の規則集合分離、死んだ構造参照の削除)と、故障セルの局所
  規則を SPEC に形式的に書き下すこと。A2 の FT 注入は設計上残る(別記)。
- (a) を選ぶなら、配置条件を m_i ≤ n_i−2(A1/A2)、m_i ≤ n_i−1(A3)に狭めた上で、
  上表の全項目を生成器に移す。境界フラグを状態に畳み込むと状態数が 2〜4 倍
  (279 → 558〜1116)になり 9 ビット索引の上限 512 を超えるので、フラグを静的入力
  (mask 由来)として扱うか規則表の表現を変える必要がある。工数は大きく、得られる
  のは「論文の文面どおりの純粋線」だが、論文の条件自体がその模型では成り立たない
  ので、忠実さの利得は小さい。

### (a) 純粋シフト線・A3 限定・n_i > m_i の設計検討(2026-11-07、ユーザー要望)

**方針**: 故障セルは純粋シフト(to_right ← 左隣の生の状態、to_left ← 右隣の生の状態。
故障セル同士はレジスタを写す)。判断は全て両隣の正常セル(I_i 右端、I_{i+1} 左端)の
規則で行う。対象は A3 のみ、配置条件は n_i > m_i(かつ論文の n_i + m_i ≥ p − i)。

#### 1. 条件 n_i > m_i で消える特殊ケース

- m_i = n_i の対が無いので、会合セルが故障セルに落ちる偶数 S の対が無い。
- m_i ≥ 1 なので **n_i ≥ 2**: 1 セルの正常区間は最終区間 I_{p+1} にしか現れない。
  したがって I_1 が 1 セル(将軍の初回 pickup、(www,M,W)→MS33)、i ≥ 2 の 1 セル
  区間の 1/3 信号((L|NG,CB,W)→LS33)、1 セル区間連続による前進対の重ね合わせ
  aFbF / aFbFT3bR、A2 用の (CB,L,W)→cBT 表示は全て対象外になる。
- スイープ: 現在の sweep_a3 1695 配置のうち m_i = n_i を含む 1266 配置が外れて
  429 配置が残る。網羅性を保つには n の範囲を広げる(p=2 を n ≤ 20、p=3 を n ≤ 22
  程度。一括モードなので数秒)。

#### 2. 時刻の整合(境界配置 m_i = n_i − 1、S 奇数)

NG が線 n_i+1 に乗るべき時刻は A3 で 2S + 1 − m_i = 3n_i。(a) の最速は、第 2 反射が
線 n_i+1 に戻る S + m_i をセル n_i が右入力に見て NG を表示する S + m_i + 1、線に
乗る S + m_i + 2 = 3n_i。**ちょうど間に合う**。現行 rust は線 n_i+1 が S + m_i + 1 に
書いて遅延線で +1 しているので、(a) では「検出が 1 セル左になる遅れ」が A3 の
+1 停留の代わりになる(この対では停留しない)。m_i ≤ n_i − 2 では会合セルが I_i の
中にあり、NG は I_i 右端で 1 歩停留(2 歩表示)して +1 を出す。実測(n=7 -f 4-5、
n=9 -f 5-6、n=11 -f 6-7)は全て 2n−2+p で SYNCED、時刻式は上と一致。

#### 3. rust 側の各処理の移し先(全て境界セルの規則になる)

境界セルは静的フラグ(左隣が故障 / 右隣が故障)を持つ。これは論文の「1/1 信号が
各正常区間の右端に着くと反射を生む」が前提にしている「右端のセルは自分が右端だと
知っている」に当たる。フラグは状態ではなく位置の属性(mask 由来)。

#### 4. 表現(状態数の上限 512 を超えない)

- 境界専用の状態(`aF_born`、`bF′`、`NG′`、`T3hold`、`L′`、解凍済み右端族、
  折り返し複合)は宿主との複合で増える。内部セルの規則表(2^27 × u16)は変えず、
  **境界セルの規則は疎な表(HashMap)** で持つ(境界セルは 2p 個なので遅くならない)。
- 内部セルが境界セルの状態を入力に見るときは**基底への射影**(bF′ → bF 担体、
  T3hold → 宿主のみ、NG′ → NG 担体、L′ → L)を通して密な表を引く。射影は規則表の
  一部として生成器が書き出す(= 規則の合成であり CA のまま)。
- rust 側は「純粋シフト」「フラグ」「境界表の参照」「射影」だけになり、現行の
  FaultField の遅延線・会合判定・1 歩記憶・own_wave 等は全て消える。

#### 5. 段階と検証(各段階を sweep_a3 の対応部分集合で確認。一括モードで数秒)

1. rust: `--pure` モード(純粋シフト+フラグ+境界表+射影)。生成器: `add_pure` が
   現行 full 規則から境界鍵を生成する足場。
2. m_i ≤ n_i − 2 のみ・最終区間 ≥ 2 セル: 横断 CB→TR、折り返し aF_born→cBT⊕aF、
   R2 装填、a/b 誕生、bF′ 停留、T3hold/abX、NG/NG′、解凍。
3. m_i = n_i − 1(右端での会合検出)、最終区間 1 セル。
4. 最終区間の 1/3 信号透過と壁消滅、解凍後の M の無視(L′)、解凍済み右端族(FT2)。
5. sweep_a3 の列挙を n_i > m_i に変え、n の範囲を広げて全緑を確認。SPEC に
   「(a) 純粋シフト線、A3、n_i > m_i」として記録(論文の n_i ≥ m_i との差異と、
   情報論的下界を理由として明記)。

#### 6. リスク

- 現行の rust には実測で見つけた特殊鍵が約 40 件あり、全てを境界鍵として再表現する
  必要がある。1 セル区間が消えることで半分程度は不要になる見込み。

- 時刻の整合は 2 で確認済み。残るのは実装の網羅だけで、原理的な障害は無い。

### スイープの一括モード `--batch`(2026-11-07)

1 配置 1 プロセスのスイープは規則表の読込(0.55 s)と 256 MB の表の確保が毎回
かかり、A3 の 1695 配置で 17 分、3 本並列ではメモリ不足でハーネスに止められた。

`batch: n=.. f=.. a3=.. SYNCED|NOT SYNCED t=.. injected=..` を出す(`batch_run_layout`:

### 検証の現状と verify / verify_seg の扱い(2026-11-06 整理)

保証は 2 層で、同期の正しさはスイープが直接検証している。

- **定理の主張の検証(スイープ)**: `sweep_a1` 305、`sweep_a2` 487、`sweep_a3`
  1695 配置、全て 0 失敗。判定は「正常セル全部が発火状態 F になった最初の時刻 =
  2n−2(+p)」と `injected signals = N`。規則表に F を含む鍵が無いので、早発火した
  セルの隣は次ステップで未定義鍵(FB、状態 0)に落ちて二度と F になれず、早発火は
  必ず NOT SYNCED になる。遅発火は報告時刻がずれて FAIL。よって緑 = 「全正常セルが
  同一ステップに発火し、それ以前に発火したセルはない」。
- **構成(凍結 Balzer 振り付け)の行単位照合**: p=1 のみ `verify_a1`(10 ケース)で
  ALL OK。`verify`(Lemma-1 バッテリ 15 ケース)と `verify_seg`(A2/A3 7 ケース)は
  ②-B 以降の機構を期待格子が知らず**履歴扱い**: 発火時刻は verify 14/15・
  verify_seg 7/7 で一致、セル照合は全件 NG(不一致は 1/3 信号の表示 `CS33`/`FmS3B`、
  担体 `CB`/`cBT`/`TR`、a/b 波 `aF`/`bF`/`bR`、`LNG` など機構の重なり)。CLI には
  残すが保証には使わない(関数 docstring に明記)。
- **Lemma 1 の範囲**: スイープが踏む Δt は配置由来(Δt_i ≥ 4)だけ。`verify` の
  (n=11, t1=7, dt=1) は 27 で発火し解凍が起きていない=凍結 1 歩後の解凍という
  縮退入力が CB 表示→1/3 信号の起動と衝突。実配置では生じないので同期保証には影響
  しないが、Lemma 1 を「任意の Δt」では主張しない(Δt ≥ 4)。
- **射影オラクル(未着手、任意)**: A2/A3 の構成照合が必要になったら、`verify_a1`
  の正規化(xNG/xR2 → ホスト)を p≥2 に広げ、機構の重なりを剥がしたホスト状態を
  素の Balzer(`golden_base`)の t_i ずらし・Δt_i 凍結と照合し、故障セルは無視する。
  工数は 1〜2 時間程度。

### 用語の改名(2026-11-06): 管路 / 入口 / 遠位口 → 故障区間 D_i / D_i 左端 / D_i 右端

### 調査中に見つかったその他事項

- **size=1 は仕様外**: ルールセットに `www ##P0 ##www` が存在しない。ruby は nil 演算で crash、golang は未定義ルール→Q で無限ループ。バグではなくルール表の対応範囲。
- ruby のパーサは `split(/(?:##|->)/)` で**末尾スペースごと名前を比較**しており、ルール行に付いている同一幅の余白(例: `Q    ##Q    ##Q    ->Q    `)と偶然整合する構造。golang は空白を剥がして比較しており、同じ結果になる。
- **rust 修復済**(2026-10-12): E0106(`Vec<AryPair<'a>>` ライフタイム)+ 未使用 import 整理 + `split()` を golang 修正と同じ不変則(実セルのみ対象 / interior ≥ 1)に書き換え。設計は golang と同じく二重バッファ共有 + mpsc トークン(rayon 論理 16 スレッド、チャネルは unbounded)。最終状態の fired チェックを main に追加(size 2..64 全部通過、size 10 の最終状態は ruby と一致)。
- **同期しないルールセットを並列実行すると rust が `RecvError` で panic する問題を修正**(2026-10-13、`-r` 導入で到達可能になった経路)。`balzer.rul.txt` の size 5 で再現。`par_simulate` の各セグメントが**自分のスライスだけで `fired()` を判定して早期離脱**するため、先に全セル F になった側が抜けて、隣が `r.recv()` で詰まる。waksman は常に同期するので今まで表面化していなかった。
  - **修正**: セグメント単位の fired をやめ、**全セグメントを固定 2n-2 ステップ回し、判定は最後に main で 1 回だけ全体に対して行う**形にした(2n-2 は FSSP の下限なので正しい解は必ずそこで発火する。golang の v1 実験と同じ形)。あわせて、2n-2 が常に偶数であることから swap 回数が偶数に戻り、最終状態が `cur` 側に載って main の `fired(&current)` が正しく効く(従来はステップ数が奇数のとき古いバッファを見ていた)。
  - **検証**: `balzer` の size 5,9,17,33,34 が panic せず `NOT SYNCED` を出すようになった。waksman / mazoyer の最終状態は debug ビルドのダンプで変更前と完全一致(size 2..1000、101 以上は並列パス)。性能は 100k で 2.20s → 1.90s(発火スキャン廃止ぶん)、200k は 5.63s / 5.59s で有意差なし。
  - 残: 逐次 `-d` 側の上限判定が `t <= 2n-2` なので、同期しない入力では 1 ステップ余分に進む(未修正。同期する入力では `fired` で先に抜けるため影響なし)。

## 教訓

- `split()` 的な区切り処理は「interior が空にならないこと」を不変則として明示的に保証する(今回の不具合はここに全部落ちていた)。
- バッチ化(一時ブロッキング)は「書き込み所有権の排他性」を崩すと破綻する。halo を書く設計には私的配列+値交換が必須。
- 実験バイナリのビルド実行は毎回ディレクトリを明示すること。cd のリセットで**別バイナリの数値を測って報告してしまう事故**が実際に起きた(v5 初回)。
**NG 会合 p=1 の実装前提で残る設計決定(2026-10-16)**:

- 委譲実装は 3 回とも出力トークン上限で中断(ファイル変更なし)。直接実装に切替。
- R2 の時刻系は解析済み: D_i 右端(to_left)の捕獲(to_right[S] 表示 @ t=S-1 なので
  I2 左端の TR 表示 @ t=S)から 1/1 左走行、セル x の表示 @ t=S+m1+n1-x、
  会合セル c_m=(S+1)/2 で t_m=(3S-1)/2、NG 右走行で I2 左端 t=2S に到達(S 奇数基準)。
- 基底 Balzer 機械の B 波は「区間半分の境目」マーカ群(2x-4 の 1/2 線+再帰的に
  密度が上がる複数 front)。R2 との会合時刻は 2S にならない(n1+m1=3 のみ)ので
  1/3 信号 S33 の別系統導入は必須のまま。
- 残る決定 = S33 の CA 位相表現。1/3 は 3 歩/セルのため単一状態では 3 歩の
  滞在カウントが書けない。候補: (a) 3 位相状態 S33/S3A/S3B と carrier を
  位相ごとに持つ(予算 3×14+3 = 45、31+45 = 76 で超過)。(b) 位相は純状態にだけ
  持たせ、carrier は「到達時刻から何歩目か」を複合名に圧縮して 2 位相へ
  (1×14+2 = 16 程度)。(c) 氷結領域は保持値を動かさないので位相を F 側
  (F(x)+位相) に 1 組だけ持つ。実装は (b)+(c) を基準に差分合成で検証する。
- I1 の凍結窓内で S33/R2/NG の 3 系統が同時に走る区間がある(n1 >= 2n2-1)ため、
  同一セル上の carrier 重畳(two-signal 競合)の規則も最終的に必要。

**NG 会合の位相解決(2026-10-16)と委譲エージェントの実測引継ぎ**:

- 機械実測(サブエージェント、(13,1,6) トレース): R2 捕獲→to_left[S]=R2@t=S+1、
  I1 内 F+R2 carrier 表示 t_R2(x)=2S+1−x(R2 は凍結 I1 のみ通過→F 側 carrier
  のみでよい)。S33 表示 t=3(x−1)。NG の必要出発 t_dep=S−1+c、pickup
  t_dep+(n1−c)、D_i 提示+1、発射表示 M@2S。
- **奇数 S の会合解**: S33 の位相 d が 1(到達表示の翌歩 = 3 歩滞在中)の表示を
  会合に使うと、標準装填のまま閉じる:
  - 偶数 S: c = S/2+1、d = 0、t_m = 3S/2(= S−1+c ✓ 3S/2)
  - 奇数 S: c = (S+1)/2(= ⌊S/2⌋+1)、d = 1、t_m = (3S−1)/2(= S−1+c ✓)
  confluence 式 3(c−1)+d = S−1+c ⟺ 2c = S+2−d。会合部は常に氷結領域。
- S33 の 3 歩滞在中の位相表示は位相付き carrier が要る。 carrier 数を 3 位相×
  (7 起床 + 7 氷結) = 42 とせず、(i) 会合に使う位相(d=0/1 の 2 位相)だけで
  良いことを確認して使う、(ii) 氷結領域は F 側の複合で位相を F(x)+位相 に
  圧縮(保持値は動かない)、(iii) 起床済みセルは実測の C 定常窓に埋め込む案
  (サブエージェント分析)で最初の実装では S33 が氷結領域のみを走る構成に絞る。
  (S33 の誕生を I1 の凍結直後に置く=論文の 1/3 放出から S33-1/3 信号 を
  「必要な区間だけ」走らせる置換装置。会合時刻式は位相 d で吸収済みなので
  時刻整合は保たれる)
- 委譲タスクは 3 回とも出力上限で中断(未実装)。以後は本体セッションで
  小刻み実装する。
